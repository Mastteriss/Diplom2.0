# ADR 0005. Windows-упаковка и обновления

## Контекст

Требуется распространять приложение под Windows в виде установщика, который можно
обновлять без потери пользовательских данных. Приложение изначально серверное
(FastAPI + Jinja2, SQLite), работает локально на `127.0.0.1:8000`.

## Решение

Приняты следующие решения:

- **Единый источник версии.** `app/config.py::APP_VERSION = "1.0.0"` — единственное
  место, откуда версия берётся для шаблонов, баннера запуска и при сборке
  установщика.
- **Замороженный бандл.** `packaging/build.ps1` собирает PyInstaller onedir в
  `packaging\dist\DiplomQuality\DiplomQuality.exe`. Спецификация `packaging/diplom.spec`
  и лаунчер `packaging/run_diplom.py` обеспечивают корректную работу в замороженном
  виде: ресурсы (шаблоны, статика, `schema.sql`, встроенный демо-файл БД) берутся
  из `sys._MEIPASS`, приложение импортируется как ASGI-объект.
- **Установщик Inno Setup 6.** `packaging/build_installer.ps1` читает `APP_VERSION`
  из `app.config`, при необходимости запускает сборку бандла, находит `ISCC.exe`
  и собирает `packaging\DiplomQuality-Setup-<версия>.exe` по скрипту
  `packaging/installer.iss`.
- **Персональная установка.** `PrivilegesRequired=lowest`, каталог по умолчанию —
  `%LOCALAPPDATA%\Programs\DiplomQuality`. Создаётся ярлык в меню «Пуск»
  («ИС анализа качества продукции»), опционально — на рабочем столе.
- **Фиксированный AppId.** В `installer.iss` задан фиксированный `AppId`, поэтому
  при запуске нового установщика поверх старого файлы программы заменяются
  (in-place upgrade), а пользовательские данные не затрагиваются.
- **Пользовательские данные вне каталога установки.** В замороженном режиме
  `app/config.py` направляет БД в `%LOCALAPPDATA%\DiplomQuality\data\quality.sqlite3`
  (с резервом `~/.diplom-quality/data`). Лаунчер при первом запуске копирует
  встроенный демо-файл `data/quality.sqlite3` в этот каталог, если БД отсутствует.
- **Упаковочно-осведомлённый код.** `app/config.py` добавляет `is_frozen()`,
  `RESOURCE_ROOT = sys._MEIPASS` при замороженном запуске (иначе `PROJECT_DIR`),
  `TEMPLATES_DIR/STATIC_DIR/SCHEMA_PATH` разрешаются от `RESOURCE_ROOT`,
  `DEFAULT_DB_PATH` и логика разрешения относительного `DIPL2_DB` адаптированы
  под записываемый пользовательский каталог. `app/web/context.py::base_context()`
  передаёт `app_version` в шаблоны.
- **Fallback без Inno Setup.** `packaging/install.ps1` копирует бандл в
  `%LOCALAPPDATA%\Programs\DiplomQuality` и создаёт ярлык; `packaging/uninstall.ps1`
  удаляет установку, по умолчанию сохраняя данные (`-PurgeData` для удаления).

## Альтернативы, рассмотренные

- **Onefile-бандл вместо onedir.** Onefile медленнее распаковывается при старте,
  сложнее отлаживать в замороженном виде, а структура ресурсов менее предсказуема.
  Выбран **onedir** (`packaging/dist/DiplomQuality/`).
- **Машинная установка в `Program Files`.** Требует прав администратора, усложняет
  обновление для обычного пользователя. Выбрана **персональная** установка в
  `%LOCALAPPDATA%\Programs\DiplomQuality`.
- **Класть SQLite-файл внутрь каталога установки.** Каталог установки перезаписывается
  при обновлении, поэтому данные будут потеряны. Выбрано хранение в
  `%LOCALAPPDATA%\DiplomQuality\data\` вне каталога установки.
- **Встроить БД прямо в EXE.** Невозможно модифицировать SQLite, хранящийся внутри
  read-only-ресурсов; кроме того, усложняет бэкап. Выбран вариант: копировать
  демо-БД в пользовательский записываемый каталог при первом запуске.
- **Ручное копирование без установщика.** Работает, но неудобно для обновления
  и менее предсказуемо. Сохранён **fallback** (`install.ps1`/`uninstall.ps1`)
  как запасной вариант.

## Последствия

**Положительные:**
- Обновление через запуск нового установщика поверх старого сохраняет
  `%LOCALAPPDATA%\DiplomQuality\data\quality.sqlite3`.
- Не требуются права администратора.
- Версия хранится в единственном месте (`APP_VERSION`).
- Код осведомлён о замороженном режиме, не ломается при упаковке.

**Отрицательные/компромиссы:**
- Приложение должно оставаться `sys.frozen`-осведомлённым: любые новые файловые
  ресурсы, читаемые из репозитория, нужно учитывать в `RESOURCE_ROOT`.
- Пользовательские данные хранятся в `%LOCALAPPDATA%\DiplomQuality\data` — их
  нужно бэкапить вручную при необходимости.
- Для сборки установщика требуется Inno Setup 6 (есть fallback без него).
- При удалении через установщик по умолчанию данные **не** удаляются — это
  осознанный выбор для сохранности пользовательских данных.
