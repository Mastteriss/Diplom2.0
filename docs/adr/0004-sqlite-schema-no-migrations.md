# ADR 0004. SQLite: идемпотентная схема без механизма миграций

## Контекст

База данных — SQLite (stdlib `sqlite3`). Контракт (`docs/contract.md` §2)
фиксирует `SCHEMA_VERSION = 1` и требует, чтобы все объекты создавались
идемпотентно через `IF NOT EXISTS`, без механизма миграций.

## Решение

* Версия схемы — константа `SCHEMA_VERSION: int = 1` в
  `app/db/connection.py`.
* `app/db/schema.sql` содержит только `CREATE TABLE IF NOT EXISTS` и
  `CREATE INDEX IF NOT EXISTS`; комментарии в файле поясняют назначение таблиц
  и правила согласованности.
* `init_db()` в `app/db/connection.py` выполняет `schema.sql` целиком через
  `conn.executescript(...)`, затем пишет строку версии
  `INSERT OR IGNORE INTO schema_version (version, name, applied_at)
  VALUES (1, 'baseline', ...)`. Повторный вызов ничего не меняет и не
  дублирует строку.
* `schema_version(conn)` возвращает `MAX(version)` из таблицы (0, если таблицы
  ещё нет) — используется в подвале страниц через `base_context()`.
* Механизма миграций (Alembic и т.п.) нет и не предусмотрено.

## Последствия

Положительные:

* Запуск и обновление схемы тривиальны: `init_db()` идемпотентен, его можно
  вызывать при каждом старте приложения (lifespan в `app/main.py` вызывает
  `init_default_db()`).
* Нет кода миграций, который надо поддерживать и тестировать.

Отрицательные:

* Изменение схемы в будущем потребует либо нового `SCHEMA_VERSION` с
  ручным переносом данных, либо пересоздания базы; автоматического
  апгрейда существующих БД нет.
* Эволюция схемы — это изменение контракта, а не локальная правка.

## Статус

Принято.
