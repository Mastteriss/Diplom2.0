# ADR 0002. Допуски параметров как норматив

## Контекст

Возникает вопрос, где в системе хранится «норматив дефектности» (ПДу — предельно
допустимый уровень). Контракт (`docs/contract.md` §3) отвечает прямо:
«Норматив дефектности в системе НЕ хранится. «Норматив» — это допуски параметра
(`lsl`/`usl`/`target` справочника `parameters_ref`)».

## Решение

Отдельной сущности «норматив»/ПДу нет. Роль норматива играют допуски
контролируемого параметра, заданные глобально в `parameters_ref`:

* колонки `target`, `lsl`, `usl` допускают `NULL` (допуск может отсутствовать);
* `CHECK (lsl IS NULL OR usl IS NULL OR lsl < usl)` гарантирует порядок границ.

Из этих допусков выводятся оба «нормативных» сравнения:

* **Соответствие допускам (критерий C2 индекса качества).**
  `app/db/repositories.py::load_period_facts` считает `in_spec` и `with_specs`
  только для параметров с обоими допусками
  (`WHERE p.lsl IS NOT NULL AND p.usl IS NOT NULL`,
  `m.value >= p.lsl AND m.value <= p.usl`). `quality_index.compute_one`
  вычисляет `C2 = clamp(in_spec / with_specs, 0, 1)`; критерий n/a при
  `with_specs = 0`.
* **Воспроизводимость процесса (SPC).** `spc.compute_spc` использует
  `parameter.lsl`/`usl` для расчёта `Cp`/`Cpk`; при отсутствии допусков
  показатель равен `None` (в интерфейсе «—», никогда не 0).

## Последствия

Положительные:

* Допуски меняются в одном месте (`parameters_ref`) и сразу влияют и на индекс,
  и на SPC.
* Нет дублирования «норматива» на уровне продукции или партии.

Отрицательные:

* Норматив невозможно задать per-product или per-line: допуск общий для
  параметра.
* Если у параметра нет обоих допусков, критерий C2 для него недоступен; он
  просто выпадает из расчёта, поэтому индекс может считаться по меньшему числу
  критериев.

## Терминологическая оговорка

Поля `quality_index_config.defect_rate_cap` и `repeat_rate_cap` — это
**коэффициенты-пороги индекса качества**, а не допуски продукции: они задают
масштаб критериев C1 и C3, а не допустимое отклонение размера. В интерфейсе
(`app/web/templates/config_weights.html`), в сообщениях валидации форм
(`app/web/pages_config.py`) и в `app/db/repositories.py::update_weights` они
подписаны «Порог дефектности» и «Порог повторяемости»; слово «Норматив» за
ними не закрепляется. «Норматив» в смысле ADR — это допуски
`parameters_ref`.

## Статус

Принято.
