# ADR 0006. Удалённый доступ и ключ доступа

## Контекст

Приложение по умолчанию слушает `127.0.0.1:8000` и доступно только на локальной
машине. Для демонстрации и работы из филиала нужен доступ с другого компьютера,
в том числе из интернета. Публичный адрес без защиты недопустим: система хранит
данные о качестве продукции и позволяет менять настройки индекса.

## Решение

Приняты два независимых решения.

- **Общий ключ доступа (`DIPL2_ACCESS_KEY`).** Переменная окружения
  `DIPL2_ACCESS_KEY` (`app/config.py::ACCESS_KEY_ENV`, читается
  `get_access_key()`). Если она непуста, `create_app()` добавляет middleware
  `app/web/auth.py::AccessKeyMiddleware`: любой запрос, кроме `GET/POST /login`,
  `GET /logout`, `/static/*` и `/favicon.ico`, без валидной сессии получает
  303 на `/login`. Если переменная пуста — защита выключена, поведение прежнее.
- **Сессия — HMAC-cookie.** `POST /login` (поле `access_key`) сравнивает
  введённое значение с ключом через `hmac.compare_digest` (константное время);
  при совпадении ставит cookie `dipl2_session` = HMAC-SHA256(ключ,
  `"diplom-quality-session-v1"`) в hex и делает 303 на `/`. Флаги cookie:
  `HttpOnly`, `SameSite=Lax`, `Path=/`, `Max-Age=2592000` (30 суток). Неверный
  ключ → 401 и повторный рендер формы. `GET /logout` удаляет cookie.
- **Публикация через быстрый туннель Cloudflare.** Лаунчер
  `packaging/run_diplom.py` по флагу `--tunnel` запускает
  `cloudflared tunnel --url http://127.0.0.1:<port>` и печатает публичный адрес
  `https://<...>.trycloudflare.com`. `--remote` включает защиту и при
  необходимости генерирует ключ (`secrets.token_urlsafe(24)`); `--access-key KEY`
  задаёт ключ явно. Туннель **инициируется только при заданном ключе**: `--tunnel`
  без ключа отклоняется с кодом выхода 2.

## Альтернативы, рассмотренные

- **Без аутентификации + allowlist по IP.** Требует стабильных адресов клиентов
  и настройки на стороне туннеля/прокси; при смене IP доступ теряется, а при
  ошибке конфигурации система открыта. Отклонено.
- **HTTP Basic-auth.** Проще в реализации, но пароль передаётся при каждом
  запросе, нет выхода из сессии, браузерный диалог плохо подходит для
  демонстрации. Отклонено в пользу формы `/login` и cookie.
- **Полноценные учётные записи (пользователи, роли, хеши паролей).** Даёт
  разграничение прав, но требует схемы БД, управления пользователями и
  существенно больше кода. Для демонстрации/филиала избыточно. Отложено.
- **VPN.** Защищает канал, но требует настройки на обеих сторонах и
  администратора; не решает задачу «показать с любого браузера». Отклонено.
- **ngrok / `ssh -R`.** ngrok требует учётной записи и токена; `ssh -R` требует
  внешнего SSH-сервера. Быстрый туннель Cloudflare работает без учётной записи.
  Отклонено.

## Последствия

**Положительные:**

- Удалённый доступ работает без учётной записи Cloudflare и без прав
  администратора.
- Защита включается одной переменной окружения; при её отсутствии поведение
  приложения не меняется.
- Ключ сравнивается в константном времени, cookie недоступна из JavaScript
  (`HttpOnly`).

**Отрицательные/компромиссы:**

- Ключ один на всех: нет разграничения пользователей и аудита, кто вошёл.
- Ключ нужно держать в секрете; утечка ключа = полный доступ. Смена ключа
  разлогинивает всех.
- HTTPS терминирует Cloudflare, приложение видит обычный HTTP на `127.0.0.1`;
  защита канала — на стороне туннеля.
- Быстрый туннель Cloudflare не предназначен для постоянного хостинга: адрес
  меняется при каждом запуске.
- Требуется `cloudflared` в `PATH`; без него туннель не поднимается (лаунчер
  печатает инструкцию и продолжает без туннеля).

## Статус

Принято.
